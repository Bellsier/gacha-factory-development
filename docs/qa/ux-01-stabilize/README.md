## C — 닫기 버튼(tdClose)이 패널 조작 요소를 가림 (`c-close-band/`)
- **원인:** 열린 패널은 자체적으로 스크롤되고, 닫기 버튼은 화면에 고정된 별도 요소입니다. 그래서 위로 스크롤한 카드 버튼이 닫기 버튼 밑을 지나가며 가려졌고, 그 자리를 탭하면 판매 대신 패널이 닫혔습니다.
- **수정 (`css/style.css`):** 패널의 `::before`(제목)를 위 여백 높이의 sticky 머리 띠로 만들고, 아이콘도 띠 안으로 옮겼습니다.
  - 띠 높이: PC 64px, 휴대폰·가로 60px
  - 내용은 띠 아래에서만 스크롤됩니다. 닫기 버튼은 띠 안에 있습니다(PC 10~54px, 휴대폰 패널 위 0~44px).
  - `scroll-padding-top`으로 키보드 포커스가 띠 밑에 숨지 않게 했습니다.
  - 버튼 숨김이나 z-index 하향은 쓰지 않았습니다.

## 03-proximity-mine — 모바일 광맥 확보 간헐 실패 (`m03-action-tap/`)
- **증상:** 광맥 앞까지 이동하고 행동 버튼(`#tdAction`) '확보'를 탭했는데도 확보되지 않아 10초 시간 초과
- **재현:** 수정 전 Pixel 7 설정에서 fresh-play 모바일 반복 시 6번째 실행에서 실패(`m03-repeat.txt`). #37 작업 중에도 10회 중 1회 실패
- **원인 (실패 실행의 이벤트 기록, `failing-run-events.jsonl`):** 버튼에 pointerdown·touchstart·pointerup·touchend는 들어왔지만 **click은 생성되지 않았습니다.** 행동 버튼이 `onclick`만 쓰기 때문에 탭이 무시됐습니다.
- **측정 (`m03-gap.cjs`):** 일반 터치 컨텍스트에서 조이스틱을 빠르게 튕긴(드래그 직후 바로 뗌) 뒤 탭했을 때 행동 실행 수
  - 수정 전: 간격 0/130/300/600ms에서 각 1/20, 1/20, 0/20, 14/20
  - 같은 측정의 click 수 기준 다른 실행에서는 18/20, 14/20, 8/20, 9/20(변동 있음)
  - 조이스틱을 60ms 유지하면 20/20
  - **수정 후: 모든 조건 20/20, 중복 실행 0**
- **분류:**
  - 테스트 타이밍만의 문제가 아닙니다. 브라우저가 빠른 드래그 직후의 탭에서 click을 만들지 않을 때 게임 행동 버튼이 탭을 놓치는 **입력 처리 약점**입니다.
  - 실제 휴대폰에서 같은 일이 생기는지는 **NOT VERIFIED**(에뮬레이션만 확인)
- **수정 (`js/topdown/app.js` `tdBindTap`):**
  - 터치·펜은 버튼 안에서 시작하고 끝난 pointerup에 실행하고, 뒤따르는 click은 한 번 무시합니다(한 탭 = 한 번).
  - 마우스·키보드(Enter/Space)·스크립트 click은 기존 click 경로 그대로입니다.
  - guard 허용 목록에 이 파일을 추가했습니다(이 처리만).
- **검사:** `tests/playthrough/action-button-tap.spec.cjs`
  - 모바일: 일반 터치 컨텍스트에서 튕긴 직후 탭 20회 각 정확히 1회
  - PC: 마우스·Enter·Space 각 1회
  - 수정 전 `app.js`로는 20회 중 15회가 사라져 실패(`spec-before-fix.txt`)
