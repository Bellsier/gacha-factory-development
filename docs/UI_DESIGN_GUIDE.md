# 《채굴 공방》 그래픽·UI 설계 기준 (2026-11-01)

> 상태: **기능과 디자인 방향 합의 / 실제 픽셀 아트·세부 치수·조작 검증은 미완료**.
> 우선순위: Blueprint 23장 최종 게임 방향을 따른다. 24장의 기존 구현 기록은 현재 상태이지 최종 UI 기준이 아니다.
> 이 문서는 디자인 기준이며, 코드를 수정하거나 기존 저장을 변경하라는 즉시 실행 지시가 아니다.

## 1. 게임 정체성

- 장르: **탑다운 2D 픽셀 아트 채굴·제작·수집·탐험·마을 생활 샌드박스**. 전통적인 RPG가 아니다.
- 정서: 따뜻하고 묵직하며 편안한 생활감. 오래된 고도 기술의 흔적이 남은 미래 지하 정착지.
- 마을은 중세 판타지 여관·성채·모험가 거점이 아니라 광부와 장인이 실제로 살아가는 공간이다. 생활 시설에 금속 설비·배관·복원 기계·부드러운 조명을 절제해 배치한다.
- 이미지 생성 종합 시안은 **배치·분위기 참고**일 뿐 최종 에셋, 정확한 비율, 문구, 조작 명세가 아니다. 과도한 RPG 장식, 두꺼운 나무 테두리, 뒤틀린 인체·가구 구조를 그대로 복제하지 않는다.

## 2. 공통 시각 언어와 HUD

- UI 콘셉트: **손때 묻은 장인의 기록**. 밝고 읽기 쉬운 양피지, 잉크 구분선, 얇은 금속 장식, 여백. 모든 창을 두꺼운 나무 프레임으로 감싸지 않는다.
- 실제 게임 세계는 양피지와 별개로 따뜻한 미래 지하 정착지. 레트로 RPG UI로 오인될 정도의 장식을 피한다.
- 기본 화면은 플레이 공간을 넓게 유지. 아래쪽에 간결한 단축 슬롯, 접근하기 쉬운 가방·지도 버튼. 기존 기능의 접근성은 보존한다.
- **미니맵은 사용하지 않는다.** 오른쪽 위에 황동 **기계식 나침반** 배치.
- 나침반은 **최대 두 바늘**: 기본 붉은 북쪽 바늘은 상시 표시, 푸른 목적지 바늘은 지도에서 목적지를 하나 선택하면 중심축에서 기계식으로 펼쳐지고 해제·도착 시 수납. 여러 목적지 중 한 번에 하나만 안내. 경로 자동 탐색은 하지 않는다.
- 카메라 북쪽 고정 여부에 따라 바늘의 상대 회전 계산을 정한다. 구현 시 카메라·좌표계부터 확인한다.

## 3. 개인 UI

- **가방과 장부는 하나의 창, 두 개의 책갈피 탭**. 가방은 Core Keeper에서 편의성만 참고한 격자형 아이템 관리(복제 금지). 장부는 플레이어 정보·선택 아이템·장비·내구도·효과를 읽는 화면.
- 장부 레이아웃은 사용자가 제시한 손그림을 기준으로: 상단 이름 / 캐릭터·아이템 그림 / 장비·효과, 하단 목록 / 가방 관련 영역 / 지도 접근을 참고. 중복 내비게이션은 와이어프레임 단계에서 정리.
- PC에서는 아이템 호버로 빠른 툴팁, 모바일에서는 탭 선택 후 장부에서 상세 확인. 선택 상태는 탭 전환 시 유지.
- 슬롯 수·창 크기·반응형 열 구성은 미확정이며 실사용 테스트로 결정한다.

## 4. 시설별 UI

| 시설 | 화면 정체성 | 핵심 구성 |
|---|---|---|
| 공방 | **위에서 내려다보는 실제 작업대** | 탁자 위 제작법 양피지·제작 도구·재료 메모, 중앙 제작 대상, 제작 수량·진행. 일반 RPG 제작 목록창으로 축소하지 않는다. |
| 창고 | 재고 장부 | 분류, 격자형 재고, 선택 품목 정보, 검색·정렬. **공용 저장소 사용성 유지**. |
| 연구소 | 연구 일지·기술 보고서 | 연구 분야, 설계도·관찰 기록, 필요 재료, 진행 상태. 판타지 마법 연구 메뉴가 아니다. |
| 박물관 | 수집품 도감 | 발견 기록·표본 그림·기증 여부·전시. 기증은 영구 보존, 전시 꾸미기와 구분. |
| 지도 | 펼친 탐험 양피지 | 지역·발견한 광맥·시설·유적·탐험 기록·목적지 지정. 미발견 장소는 과도하게 공개하지 않는다. |

## 5. 생활 UI

- 집 안은 캐릭터가 직접 이동하고 가구를 조사한다. 의자 앉기·침대 휴식·책장 읽기 등은 해당 기능이 구현될 때 작은 상호작용으로 제공.
- 가구는 공방에서 제작하고 **가방에서 선택해 월드에 직접 배치**한다. 위치 미리보기, 가능한 경우 회전, 충돌 방지, 무료 회수·재배치, 위치·방향 저장을 목표로 한다. 별도 강제 꾸미기 모드 불필요.
- 주민 대화는 작은 양피지 대화창, 게시판은 붙어 있는 의뢰서, 상점은 상품 장부와 계산대, 편지는 읽는 양피지. 정원 꾸미기도 직접 배치.
- 아직 없는 수면·상점·가구 제작 등은 **향후 구현 대상**으로 표시하고 현행 구현으로 오인하지 않는다.

## 6. 그래픽 품질 기준

- 캐릭터 정면·측면·후면 및 이동 프레임에서 **양쪽 다리·팔이 명확히 구분**되어야 한다.
- 건물은 실제 용도(공방 제작, 집 생활, 박물관 역사)가 읽히도록 크기와 입구·설비를 검토한다.
- 자연 지형은 반복 타일·RPG식 직각 경계를 완화하되 채굴 대상·통행 가능 공간은 분명하게 표시.
- 따뜻한 생활 조명과 차가운 광물·기술 조명을 구별하되 과도한 장식·입자 효과는 피한다.
- 이미지 생성 결과를 픽셀 단위의 완성 에셋으로 간주하지 않는다. UI는 HTML/CSS 실제 배치로, 스프라이트는 픽셀 규격과 애니메이션 검수로 확정.

## 7. 구현 순서와 검증 게이트

1. 본 문서 승인·병합.
2. **기본 HUD와 기계식 나침반**을 독립 Task/PR로 구현.
3. 가방·장부 통합 UI.
4. 공방 작업대 UI.
5. 창고·연구소·박물관·지도.
6. 생활 UI 및 가구 상호작용(현행 구현과 미구현 기능 구분).
7. 캐릭터·건물·지형 에셋 정합성 개선.

각 단계는 PC·모바일 레이아웃, 키보드·터치 조작, 가독성, 기존 채굴·제작·창고·연구·저장 회귀 테스트를 통과해야 다음 단계로 넘어간다. 기존 `saveVersion 1`과 사용자 세이브를 무단 변경하지 않는다. **PR 병합은 별도 승인 필요.**

## 8. 참고 시안 사용 원칙

2026-11-01 대화의 종합 UI 이미지(마을·나침반·지도·가방·공방·집·창고·연구소·박물관·주민 UI)는 **구도와 정보 배치 참고용**이다. 현재 이 문서에는 이미지 바이너리를 첨부하지 않았다. 추후 별도 검수된 이미지가 저장소에 등록되면 경로를 연결한다. 그림의 RPG풍 외관과 생성 오류는 디자인 결정으로 취급하지 않는다.
