# 월드 확장 3단계 — 승인 설계와 구현 계약

사용자 승인: 2026-10-19. 기준 `claude/chunk-index-v1` / `d7fb835f53deadafeee6e2acca8d7694f956a0aa`.
최종 목표 2048×2048, 이번 활성 범위는 **256×256**. 기존 PR 병합, Pages 변경, 기존 그래픽/캐릭터 파일 수정 금지.

## 구조
- 1단위=4타일, 32×32타일=8×8단위 청크. 시험은 [-32,32) 단위, 8×8청크.
- `chunkgen.js`: seed(uint32), generatorVersion=1, 절대 좌표에서 순수 생성. 전역 상태/시간/Math.random/캐시 순서 비의존. 해시 채널 1..6, 고정 정수 혼합, 16타일 노이즈와 Q16 보간. 광맥 8타일 셀당 최대1개, 소품2타일 셀당 최대1개.
- `worldchunks.js`: 데이터 Map, 생성 광맥 레지스트리, 합성, 변경 기록, 시험 UI. TD 캔버스 캐시와 독립. 최대64개 데이터이며 2048 스트리밍/워커/LRU는 후속 단계. 미니맵은 전체64청크를 요청할 수 있다.
- 기존 [-12,12) 영역은 기존 타일과 절대 좌표 그대로. 바깥2단위는 숲 경계. 외곽과 기존 지역은 이번 단계에서 걸어서 연결하지 않는다. 기존 도로/터널 규칙을 보존하고 시험 전용 왕복으로 외곽을 검사한다.
- 외곽 통행은 절대 좌표의2타일 폭 연결 격자와 광맥 접근 통로. 바닥/충돌이 같은 타일 정보를 사용한다. 광맥 접근 통로는 해시 후보만 참조해 재귀 의존을 피한다.
- 기존 픽셀 텍스처는 원래 (-12,-12) 좌표 기준을 유지하는 어댑터를 tiles.js에 둔다. sprites.js/style.js/hires.js 및 CSS와 기존 자산은 변경하지 않는다.

## 저장 계약
- `?worldgen=256`에서만 활성. 기존 `gachaFactorySave`는 읽기만 하고, 쓰기는 `gachaFactorySave.worldgen256.v1`만 사용.
- trial 없으면 legacy를 복사. 둘 다 없으면 기존 새게임+시험 메타데이터. 손상/future trial은 legacy로 덮어쓰지 않음.
- saveVersion1 유지, world에 `seed`, `size:256`, `generatorVersion:1`, `chunkEditsVersion:1`, `chunkEdits` 추가.
- `chunkEdits["cx,cy"].mines["gen:v1:mine:gx:gy"]={discovered:boolean,developmentState:"unsecured"|"secured"}`. 확보이면 발견=true. gx/gy는 절대8타일 셀.
- 시드/생성 버전은 저장 수명 동안 불변. 새 시드는 새 시험 저장. 알 수 없는 버전/크기, 손상 변경 기록은 로드 거부 및 저장 차단.
- 변경 기록은 최대64청크×16광맥, 실제 생성 후보 및 청크 소유권 검증. 기존ID 충돌 시 삭제 대신 로드 거부.
- 메타데이터를 먼저 읽은 context로 외곽 플레이어/횃불/작업장 좌표를 검증.
- runtime mines에는 생성 광맥을 합성하지만 저장 projection에서 레지스트리 소유 객체만 제거. 원형 타일/소품/캐시는 저장하지 않음.
- 발견/확보는 변경 기록에 동기 반영. 채굴은 기존 자원 필드에만 기록: 현재 게임에는 고갈이 없음.
- 일꾼 광맥 배치는 기존 코드에서 파생됨. 저장된 변경 기록 광맥을 부팅 때 복원한 뒤 같은 mineId/위치가 나오는지 테스트. 별도 배치 권위 데이터는 도입하지 않음.
- 시험 왕복은 원래 플레이어 위치를 보존하는 `testReturnPosition` 사용. 시험모드 밖에서는 함수도 false, 버튼도 없음. 외곽 시작은(16,0).

## 검증 계약
1. 100개 시드×64청크, 생성 순서/재실행/음수 경계/절대 타일 조회/golden hash.
2. 기존 타일·충돌, 마을 정적픽셀, 전이띠에 생성 엔티티 없음, 외곽 통로 연결, 4청크 합성픽셀.
3. 기존 midgame 및 신규 저장: 좌표/진행/영구 상태 보존, 원본 문자열 불변.
4. 발견→확보→채굴→저장→로드, 일꾼 참조, 외곽 작업장/횃불, 환생, 미래 버전/손상/ID 충돌.
5. 실제 Chromium PC/모바일: 키/터치, 광맥 E/행동버튼, 재로드, 콘솔, 스크린샷.
6. PC1280×800/DPR1, Chromebook1366×768/DPR1, mobile390×844/DPR3, CPU1×/4×는 **에뮬레이션**.
7. 성능: cold10/warm10, 생성64×30회, 30초 이동. p50/p95/p99/max, long tasks, 데이터 byteLength/heap 및 캔버스 추정은 별도 수치.
8. 목표: 생성p95 4ms(1×)/12ms(4×), 생성데이터 retained heap8MiB, 일반렌더캐시25장, framep95 33.4ms/50ms. 미달은 숨기지 않고 보고.
