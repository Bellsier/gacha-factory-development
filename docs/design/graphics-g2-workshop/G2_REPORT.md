# G2 공방 외관 시안 평가

## 결론과 범위

**B안 — 장인의 작업장형을 우선 추천한다.** 기존 적갈색 지붕과 목조 건물을 유지하면서 작업대·모루·재료 선반으로 제작 시설의 용도가 가장 분명해진다. 최종 시안 선택과 정식 게임 적용은 아직 승인되지 않았다.

2026-11-02, 최신 develop `ab0ad8c464319bbaf2735e4a46998050878f17f0`에서 `codex/graphics-g2-workshop-proposal`을 분기했다. 변경은 이 문서 폴더에 한정된다. 게임의 index.html, js/, css/, 저장 시스템, 기본 classic 설정은 변경하지 않았다. G3 집·G4 박물관은 시작하지 않았다.

참조: [G0 아트 디렉션](../graphics-g0-g1/G0_ART_DIRECTION.md), [그래픽 계획 G2](../graphics-g0-g1/GRAPHICS_PLAN.md), [BLUEPRINT V3](../../BLUEPRINT_V3.md), [UI 디자인 가이드](../../UI_DESIGN_GUIDE.md). 미래 시대의 따뜻한 마을이라는 최신 G0 방향과 사용자의 이번 지시를 기준으로 삼았다.

## 실제 화면과 비율 평가

[README의 조건별 PNG 표](README.md#실제-게임-화면-바로-보기)와 [비교 HTML](G2-workshop-compare.html)에서 동일 조건의 기존/A/B/C를 확인할 수 있다. 비율표는 직접 조합한 픽셀 비교이며, `pc-*`, `mobile-*`, `dusk-*` PNG는 실제 index.html의 게임 렌더러로 촬영했다.

- **PC 1280×800, DPR 1, 게임 확대 3배:** B의 작업대와 재료 선반이 구분된다. A의 창틀·처마 변화는 작지만 정돈된 인상을 준다. C의 장치 외형과 배관이 보이며 집보다는 작업 시설로 읽힌다. 주변 풀·길·마을 시설과 같은 따뜻한 갈색 계열이다.
- **모바일 390×844, DPR 3, 게임 확대 2배:** 공방 전체와 출입구가 UI에 가리지 않고 보인다. B의 작업대/선반이라는 큰 형태는 유지되지만 망치·작업등 같은 1픽셀 정보는 축소되어 약하다. C의 작은 계기는 의미 전달이 약하다. 실제 휴대폰이 아닌 Chromium 모바일 에뮬레이션 결과다.
- **classic:** 기존의 평평한 픽셀 면과 잘 맞는다. 추가한 판재 음영과 처마 명암이 입체감을 조금 보강한다.
- **v2:** 기존 `tdStyleFinish(..., 'building')`를 그대로 적용해 외곽과 모서리를 정리한다. 주변 지형과 G1 캐릭터의 v2 표현에 맞으며 별도 고해상도 실험은 사용하지 않는다. 기본 스타일은 classic 그대로다.
- **G1 비율:** 공방 64×58 / 캐릭터 16×22. 원본 캔버스 기준 너비 4배, 높이 약 2.64배다. 공방 (32,54), 캐릭터 (8,21)을 같은 지면에 맞췄다. 문 14×20은 기존과 완전히 동일하며, 캐릭터 대비 출입구가 더 작아지는 변화는 없다. 작은 제작 공방으로 읽히는 기존 축척을 유지한다.
- **저녁:** 기존 조명의 가장 어두운 단계(0.34)에서도 문·창·작업대의 큰 형태가 읽힌다. 작은 장식은 낮보다 약하다. 두 창문 광원은 기존 좌표를 사용한다. C의 계기와 B의 작업등에는 별도 발광 효과를 추가하지 않았다.

## 촬영 조건과 격리

- 난수: LCG 시드 `20261101`, 새 격리 브라우저 컨텍스트. 각 기기/스타일 안에서는 같은 게임 상태를 네 시안이 공유한다.
- 플레이어: 공방에서 월드 좌표 `(+0.45, +0.65)`, 아래를 바라보는 정지 자세. 카메라는 기존 추적 함수를 사용하며 매 조건의 좌표를 JSON으로 보존한다.
- 프레임 시각: 낮 `tdRender(0)`, 저녁 `tdRender(240000)`. 실제 렌더러의 조명은 Date.now도 사용하므로 기존 시험용 `TD.forceDarkness`에 각각 0.10/0.34를 명시한다.
- 실제 게임 타이머를 멈추고 지형·미니맵 캐시 및 기존 안내창 투명도 전환을 준비한 다음 촬영한다. 품질 단계는 0으로 통일한다. 키보드 검증은 별도로 정상 tick 타이머를 재개한다.
- 교체 대상은 `TD.sheet.base`의 Canvas 이미지 하나다. 게임 소스, 기본 스프라이트 함수, 충돌 상자, 월드 시설은 교체하지 않는다.
- 비교 HTML은 저장 API와 게임 스크립트를 사용하지 않는다. 캡처 브라우저도 부팅 전부터 메모리 저장소로 격리한다. 실제 저장 데이터 호환성을 바꾸는 코드 자체가 없다.
- 외부 폰트 요청은 재현성을 위해 빈 CSS로 대체한다. 화면은 로컬 대체 폰트를 사용하므로 배포본의 글자 폭과 다를 수 있다.

## 추가 승인이 필요한 사항

1. A·B·C 중 최종 선택 또는 혼합 방향.
2. 선택된 그림을 정식 게임에 적용하는 별도 작업과 PR 병합.

이번 Draft에는 검토 자료만 보존한다. develop 병합, 기본 스타일 변경, 새 광원·외부 장식·충돌 확장, G3/G4 작업은 수행하지 않는다.
