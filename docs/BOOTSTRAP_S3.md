# S3 초기 화면 노출 수정 — PR28

## 원인과 변경

기존 HTML은 즉시 게임 UI를 표시하고 tdInit이 기본 월드를 그리는 반면 S2 저장소/목록 조회는 비동기였다. 재방문 선택 화면도 반투명 배경이라 아직 선택하지 않은 마을의 기본 게임 화면이 보였다.

첫 HTML에 critical CSS, 불투명 로딩 화면, 작은 CSS 픽셀 집과 상태 문구를 포함한다. 외부 CSS·폰트·게임 스크립트 없이도 이 화면을 표시한다. 필수 메인 CSS는 비동기로 읽되 명시적 완료 신호를 기다린다. 저장소/목록/뷰 구성 완료, DOMContentLoaded(모든 parser 스크립트), 메인 스타일 완료 후 첫 렌더를 수행하고 프레임 경계에서 표시한다. 폰트 다운로드는 필수 조건이 아니다.

아직 선택한 마을이 없는 상태에서는 완성된 저장 메뉴만 표시하고 게임 배경을 숨긴다. 마을 이어하기는 기존 S2 절차대로 수행하며 실제 대상 장면을 그린 뒤 표시한다. 데이터 포맷·키·DB 스키마·최근 마을 기록·Web Lock·writerEpoch·인계 확인 로직은 바꾸지 않았다.

## 실패와 재시도

초기 저장소/목록 실패, 필수 스크립트·스타일 오류, 미처리 초기화 예외와 20초 시간 초과는 오류 안내와 다시 시도 버튼으로 전환한다. 본문 생성 전에 난 오류도 DOM 요소가 생기는 즉시 표시하므로 DOMContentLoaded를 무한히 기다리지 않는다. 오류 상태는 해당 문서에서 되돌리지 않는다. 늦은 초기화 완료도 게임을 노출하거나 플레이·자동 저장을 시작할 수 없다. 재시도는 페이지 새로고침이며 기존 저장을 삭제/초기화하거나 권한 확인을 생략하지 않는다.

단일 HTML 배포 파일에도 같은 게이트를 포함한다. 인라인으로 패키징된 메인 CSS는 build-dist.js에서 준비 완료 신호를 보낸다. 기존 legacy/trial 경로와 테스트 라이브러리 부팅 계약은 유지한다.

## 재현과 검증

`CHROMIUM=/usr/bin/chromium npm run test:bootstrap` (CI에서는 설치된 Playwright Chromium 사용)

1. 첫 HTML에서 메인 CSS와 첫 게임 스크립트를 보류 → 로딩만 보임 → 해제 후 완성 게임 표시.
2. 재방문에서 마을 목록 조회를 보류 → 메뉴 중간 상태 숨김 → 목록 완료 후 선택 메뉴만 표시, 기본 월드는 숨김.
3. 목록 조회 실패 → 오류/재시도 → 새로고침 후 같은 최근 마을 및 데이터로 이어하기.
4. 모바일 IndexedDB 초기화를 보류 → 로딩만 표시 → 완료 후 정상 화면.
5. 저장소 접근 불가 → 쓰기 금지/오류 → 재시도 후 기존 localStorage 원문 불변과 gold321 복원.
6. 저장소 응답이 없는 상태에서 가상 시계를21초 진행 → 오류/재시도 → 늦은 완료도 오류 화면 유지·플레이 차단.
7. HTML head에서 오류를 발생시키고 후속 스크립트를 보류 → DOMContentLoaded 이전에도 재시도 표시.
8. 메인 CSS 로드 실패 → critical CSS로 오류 화면/재시도 유지, 게임 UI 숨김.
9. S2 runtime 스크립트404 → 기존 저장 쓰기로 되돌아가지 않음 → 재시도 후 정상 복원.

기존 38개 S2 브라우저 그룹은 수정하지 않고 함께 실행한다. 전체 회귀2781, 기존 smoke, Biome와 단일 HTML/ZIP 생성도 확인한다. 테스트와 오류 주입은 새 브라우저 컨텍스트·임시 localhost에서만 수행하며 사용자 저장/배포 origin에 접근하지 않는다. PC/모바일 로딩 및 오류 화면은 `docs/screenshots/bootstrap-s3/`에 기록한다.

이번 작업은 PR28의 소스 수정과 CI 검증이다. develop 및 S3 Sites 미리보기 모두 재배포하지 않으며, PR은 Draft로 유지한다. G4 변경은 없다. 모바일은 Chromium 에뮬레이션 기준이다.
