# Issue #32 A: fresh-play 자동 저장 대기 경합

- **증상:** `fresh-play.spec.cjs` `09-refresh`에서 새로고침 뒤 인부 수가 기대 1, 실제 0으로 가끔 실패
  - #36 로컬 PC와 CI 모바일 attempt 1에서 관찰됨
- **원인:** `07-autosave`가 커밋된 자동 저장의 `gold === 50`만 기다렸습니다. 판매 직후의 **이전 자동 저장도 골드가 50**이라, 인부가 들어가기 전의 커밋으로도 대기가 끝났습니다. 그 직후 새로고침하면 인부 0명이 불러와집니다.
  - 저장 엔진의 손실이 아니라 **테스트 대기 조건의 문제**입니다.
- **수정:** 테스트 쪽만 고쳤습니다. 저장 엔진, 자동 저장 주기, saveVersion1, 게임 코드는 바꾸지 않았습니다.
  - `06-first-worker`에서 인부를 배치한 직후, 그 마을의 **커밋된 revision**과 메모리의 골드·인부 수·배치를 기록합니다. 읽기만 합니다.
  - `07-autosave`는 같은 마을 ID이고 **기록한 revision보다 새 커밋**이며, 그 커밋에 골드·인부 수·배치가 모두 들어 있을 때까지 기다립니다.
    - 판정: `tests/playthrough/save-wait.cjs` `commitReady()`
    - 대기 한도: 25초. 자동 저장은 바뀐 것이 없어도 10초마다 커밋합니다.
  - `09-refresh`에서는 새로고침 뒤 인부 배치도 같은지 확인합니다.
  - 고정 sleep, `waitForTimeout`, 무제한 polling, 엔진 우회는 쓰지 않았습니다.
  - 저장 레코드 필드는 실제 `SaveEngine`에 있는 것만 씁니다: `id`, `revision`, `snapshot.payload.{saveVersion, run}`.
