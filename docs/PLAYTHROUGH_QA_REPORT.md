# 자동 플레이 QA — 1차 결과 기록

게임 기준: PR #28 `f5169308b1659913119f8b035e5998a0543c538d`. 게임 코드·밸런스·저장 엔진은 변경하지 않았다. 이 문서는 로컬 실행의 도달 지점과 확인된 문제를 보존한다. 최종 GitHub Actions 실행 URL, 테스트 SHA와 artifact 결과는 별도 Draft PR 본문 및 Checks에 기록한다.

## 실행과 도달 범위

로컬 시스템 Chromium에서 PC1280×800, 모바일390×844·터치·DPR1을 사용했다. 새로운 context와 localhost의 테스트 저장만 사용했다. 전체 회귀 2,781개가 통과했고, 새 플레이 시나리오 10개(환경별5개), 검증 단계104개가 통과했다. 보고서의 실패 전파·실행기 실패·설치 실패 증거·원본 결과 보존 검사4개도 통과했다. 기존 S2 38개와 부트스트랩9개 검사는 수정하지 않았으며 새 CI에서도 실행한다.

- 무주입: UI로 새 마을 생성 → 실제 이동·벽 충돌 → 광맥 접근/E 또는 터치 채굴 → 자원 수집 → 강철10개 제작·판매/50G → 첫 인부 모집·배치 → 실제 자동 저장 타이머 → 수동 저장 → 새로고침/최근 마을 → 새 사본 복원. 원본 마을 자동 저장과 원본 수동 저장을 보존했다.
- 후반: 준비 자원만 1회 제공한 뒤 버튼 조작으로 지역4곳, 연구9개, 터널 의뢰·개통, 18개 모든 제품 신규 제작, 제작소8곳/첫 제작소Lv8, HQ12/제작시설15, 철 채굴·인력시설12, 인부3능력 강화, 첫 납품, 감정소·박물관 복구와18종 전시, 최종 황금 곡괭이 기념비 배치·회수까지 도달했다.
- 별도 시나리오: 느린 저장소 초기화/로딩, 저장소 오류/재시도, 수동1~5 슬롯 저장·덮어쓰기·삭제와 마을 자동 저장 보존.

**무주입 전체 플레이를 완주한 결과는 아니다.** 후반은 골드·재료·미감정 유물을 준비한 검사이고 터널은 브라우저 시계를600초 전진시켰다. 모든 고정 수주·정기 거래, 전 자원/인부/제작소의 반복 최대 강화, 월드 전체 탐색은 완주하지 않았다. 다음 수주의5~25분 대기는 미도달로 기록한다. 전투·고대 지하 도시·스토리 등 최종 설계의 미구현 항목도 실패와 별도로 표시한다. 로컬 영상 다운로드는 환경의403 Domain forbidden으로 불가능해 영상 없이 trace/스크린샷을 수집했다. CI는 Playwright Chromium·영상 다운로드와 실제 영상 업로드를 별도로 검증한다.

## 확인된 문제

아래 문제는 기능 E2E의 통과와 별도로 기록한다. 이 QA PR에서는 게임 UI를 수정하지 않는다. 모든 화면은 대체 웹폰트 기준이다.

### QA-UX-01 — 고정 저장 HUD가 패널 본문을 가림

- 심각도: UX 개선.
- 위치: PC 인부·납품·박물관 패널, 모바일 인부 패널.
- 재현: PC에서 인부/납품 패널을 열거나 후반 마을 패널을 박물관까지 스크롤한다. 모바일390×844에서 인부1명을 모집한 뒤 인부 카드가 보이도록 둔다.
- 기대: 패널 설명과 능력치를 가리지 않는 저장 HUD 배치.
- 실제: PC 우측 `저장 · 마을` 버튼이 박물관의 ‘결정처럼 단단하게 굳은 깃털.’ 같은 본문 및 납품 설명을 덮는다. 모바일 하단의 현재 마을/자동 저장 상태는 인부 능력치 줄을 덮는다.
- 증거: [PC 저장 버튼 가림](screenshots/playthrough-qa/pc-save-button-overlap.png), [모바일 인부와 상태 HUD](screenshots/playthrough-qa/mobile-worker-hud.png). artifact의 `12-museum-passed.png`, `10-delivery-passed.png`, `06-first-worker-passed.png` 및 layout 관찰값.
- 추정 원인: `css/style.css`의 `#s2Open`(fixed/right/top150px), `#s2Status`(fixed/bottom78px, 모바일88px)가 패널보다 높은 z-index를 가지며 본문 공간을 예약하지 않는다.
- 권장: 패널 밖 공통 HUD 영역으로 이동하거나 패널 표시 시 상태 배치를 조정하고 본문 여백을 확보한다.

### QA-UX-02 — 모바일 선택/수량 입력의 작은 터치 영역

- 심각도: UX 개선.
- 위치: 인부 담당 자원 선택, 납품 제품 선택·수량 입력.
- 재현: 모바일390×844에서 인부를 모집해 인부 패널을 연다. 준비 자원 여정에서는 납품 계약 연구 후 납품 패널을 연다.
- 기대: 주요 입력의 터치 영역이 최소44px이고 인접 조작을 누르기 쉽다.
- 실제: 인부 선택 높이38px, 납품 선택/수량 높이40px로 측정됐다. 이 크기는 기능 클릭 실패와는 별개의 조작 편의 문제다.
- 증거: [모바일 인부 선택](screenshots/playthrough-qa/mobile-worker-hud.png), artifact `06-first-worker-passed.png`/`10-delivery-passed.png`, journey.json의 small 측정값(79×38, 250×40, 80×40px).
- 추정 원인: 탑다운 공통 select/input의 min-height36px와 각 필드 패딩.
- 권장: 모바일 주요 select/input의 터치 높이를44px 이상으로 통일한다.

- 심각도: 경미.
- 위치: 모바일 상단 다음 할 일 아래.

- 권장: 저장 표시를 하나로 통합하거나 기존 문구에도 읽을 수 있는 배경과 레이아웃을 제공한다.

## 검사 구축 중 구분한 실패

- 테스트의 박물관 수집 수 기대가20으로 잘못 작성되어 실패했다. 실제 데이터는 유물12+표본6=18이고 최종 보상은18점이다. 테스트 기대만 수정했으며 게임 결함으로 보고하지 않는다.
- CSS를 보류한 로딩 스크린샷은 Playwright의 fonts.ready 대기와 충돌했다. 저장소 초기화 응답을 보류하는 환경 fixture로 변경해 로딩을 촬영했다. 기존 부트스트랩9개 검사의 CSS 실패/느린 HTML 검사는 유지한다.
- 접힌 자동 저장 details 안의 버튼이 geometry에서 잡히는 오탐을 발견했다. 회귀 검사로 재현하고 닫힌 details의 본문은 제외했다. 모달 뒤의 의도적으로 가려진 배경 조작도 제외한다.

검사에 나타나지 않은 버그의 부재나 모든 콘텐츠 완주를 주장하지 않는다. 브라우저 재실행·실기기·고DPR·다른 브라우저·외부 폰트 자체의 품질은 별도 검증이 필요하다.
