## 1. 기준 문서 대조

### 1.1 요청하신 6개 질문

**Q1. UI 가이드가 실제로 양피지 스타일을 요구하는가 → 예, UI(창)에 대해서는 명시적으로 요구합니다.**
- 원문 §2: "UI 콘셉트: **손때 묻은 장인의 기록**. 밝고 읽기 쉬운 양피지, 잉크 구분선, 얇은 금속 장식, 여백. 모든 창을 두꺼운 나무 프레임으로 감싸지 않는다."
- 범위: 같은 §2에 "실제 게임 세계는 양피지와 별개로 따뜻한 미래 지하 정착지"라고 되어 있습니다. 양피지는 **UI 창의 기준**이고, 월드 그래픽의 기준이 아닙니다.
- 시설 UI에도 양피지가 나옵니다(§4: 공방 탁자 위 "제작법 양피지", 지도 "펼친 탐험 양피지", §5: "작은 양피지 대화창", "읽는 양피지").
- 불명확한 점: 양피지의 명도·색값, 창 테두리 두께, HUD(화폐·안내판·독)도 양피지로 하는지는 정하지 않았습니다. §8 1단계 "아트 디렉션 규격"에서 정할 항목입니다.

**Q2. 목재·구리 테마가 가이드와 충돌하는가 → 부분적으로 충돌합니다(방향 충돌). 시간 순서상 가이드가 나중 결정입니다.**
- 현재 테마(Task 24, `88585f9`, 2026-10-31 병합)
  - 패널 배경: 짙은 목재(#2a2018 계열)와 판자결 무늬
  - 패널 테두리: 2px 목재 + 1px 구리선
  - 누를 수 있는 것: 구리, 켜짐·완료: 청록
  - 이 테마는 Task 24 지시서 원문("따뜻한 목재·구리·짙은 청록색을 기본으로")을 따랐습니다.
- 가이드(`26cee0b`, 2026-11-01 병합): "밝고 읽기 쉬운 양피지", "모든 창을 두꺼운 나무 프레임으로 감싸지 않는다", "레트로 RPG UI로 오인될 정도의 장식을 피한다"
- 충돌하는 부분
  - **명도:** 짙은 목재 배경 ↔ 밝은 양피지
  - **재료:** 목재 판 ↔ 양피지 + 얇은 금속
- 충돌하지 않거나 불명확한 부분
  - 2px 테두리가 가이드가 금지한 "두꺼운 나무 프레임"인지는 원문만으로 판단할 수 없습니다.
  - "얇은 금속 장식"은 구리선과 같은 방향입니다.
  - 구리·청록 강조색을 양피지 위에서 계속 쓸 수 있는지는 가이드에 없습니다.
- 처리: **결정 필요(D1).** 가이드가 더 최신이고 청사진 머리말이 가이드를 따르라고 하므로, 가이드 쪽으로 옮기는 것이 문서상 일관된 방향입니다(추천). 다만 시점·범위(HUD까지 바꾸는지)는 사용자 결정입니다.

**Q3. 기계식 나침반과 기존 미니맵의 관계 → 가이드는 미니맵을 쓰지 않는다고 명시합니다. 그러나 미니맵이 맡던 기능을 어디로 옮길지는 단계별로 정해져 있지 않습니다.**
- 가이드 §2
  - "**미니맵은 사용하지 않는다.** 오른쪽 위에 황동 기계식 나침반"
  - "최대 두 바늘: 붉은 북쪽 바늘 상시, 푸른 목적지 바늘은 지도에서 목적지를 하나 선택하면 펼쳐지고 해제·도착 시 수납 … 경로 자동 탐색은 하지 않는다"
  - "카메라 북쪽 고정 여부에 따라 바늘의 상대 회전 계산을 정한다"
- 청사진
  - 3.5 "탐험 지도 (기존 UI 기준, **최종 지도 확장 예정**)": 미발견 광맥을 지도에 표시하지 않는 원칙은 유지할 수 있음
  - 24.2: "미니맵"은 구현 항목, 24.7: 미니맵은 오른쪽 위
- 관계 정리
  - 기존 미니맵이 맡던 "발견한 광맥·거점·플레이어 위치 표시"는 가이드 §4의 **지도 화면**("펼친 탐험 양피지 … 발견한 광맥 … 미발견 장소는 과도하게 공개하지 않는다")으로 옮겨 가는 것으로 읽힙니다.
  - 지도 화면은 **미구현**입니다.
- 사실 확인(코드): 현재 카메라는 회전하지 않습니다(북쪽 고정, `topdownCamera`). 그래서 북쪽 바늘은 항상 위를 가리키고, 목적지 바늘이 생기기 전까지는 정보가 거의 없습니다.
- 위험: 지도 화면 없이 미니맵만 먼저 빼면 "발견한 광맥 위치 확인" 기능이 사라집니다. 가이드 §2 "기존 기능의 접근성은 보존한다"와 부딪힙니다.
- 처리: **결정 필요(D2).**
  - 선택 1(추천): 미니맵 제거를 지도 화면·목적지 바늘이 생기는 시점과 묶습니다.
  - 선택 2: 나침반을 먼저 놓고 미니맵을 임시로 함께 둡니다.

**Q4. "미래의 지하 정착지" 세계관 표현 기준 → 가이드와 청사진의 서술이 다릅니다. 확정하지 않고 결정 필요로 둡니다.**
- 가이드 §1
  - "정서: … 오래된 고도 기술의 흔적이 남은 **미래 지하 정착지**"
  - "마을은 중세 판타지 여관·성채·모험가 거점이 아니라 광부와 장인이 실제로 살아가는 공간이다. 생활 시설에 금속 설비·배관·복원 기계·부드러운 조명을 절제해 배치한다."
- 청사진
  - 1장·23.2·23.9: "**푸른 초원**의 시작 마을을 거점으로 **지상 7개 지역**…", "시작 마을은 푸른 초원 안에 위치하는 거점"
  - 23.3: **고대 지하 도시 B1~B4**는 플레이어가 사는 곳이 아니라 비전투 **탐험 구역**(옛 문명의 유적)
  - 23.4: 세계관에 과학자·기계·수로 기술(안개 늪지)·인공 수정 연구 등 기술 요소가 있습니다. 다만 시대가 "미래"라는 서술은 청사진 어디에도 없습니다.
- 다른 점
  1. 플레이어 거점이 **지하**인가(가이드) **지상 초원**인가(청사진)
  2. **"미래"**라는 시대 설정
- 공통점: 양쪽 다 "고대(옛) 기술의 흔적"이 있고, 판타지 성채·여관풍이 아닌 "광부와 장인의 생활 공간"(가이드)과 "쇠퇴한 공동체의 회복"(청사진 23.9)이라는 생활감은 같은 방향입니다.
- 처리: **결정 필요(D3).** 해석 후보는 다음과 같습니다(확정 아님).
  - (a) 지상 초원 마을에 고대·고도 기술의 흔적(금속 설비·배관·복원 기계)을 절제해 섞습니다.
  - (b) 가이드 문구를 지상 마을로 고칩니다.
  - (c) 청사진을 지하 정착지로 바꿉니다(큰 세계관 변경).
  - 그래픽 작업 범위는 (a)로 읽어도 (b)로 읽어도 거의 같습니다. (c)는 월드 설계 변경이라 이번 그래픽 범위 밖입니다.

### G5. 산맥 경계와 암석 무늬 (3순위-1)
- **범위:** `tiles.js`의 **그리는 부분만**(`tdPaintTileMap` 등, `COLLABORATION.md` §2). 타일 종류 규칙(`tdTileAt`)과 지형 데이터는 바꾸지 않습니다(Codex 영역).
- **개선 내용**

  - 반복 무늬에는 위치 기반 결정적 변형(같은 좌표 = 같은 그림)을 넣습니다.
- **기대 차이:** 같은 무늬가 일정 간격으로 되풀이되는 현상과 계단형 경계가 눈에 띄게 줄어듦. 바위와 땅의 경계는 충돌과 1:1로 일치.
- **영향**
  - 256 시험 월드의 청크 그리기(`worldtileview.js`의 `worldPaintTileMap`)도 같은 `tdPaintTileMap`을 부르므로 함께 바뀝니다(코드 확인).
  - 청크 경계 이음새 테스트(09.js, 20.js "chunk canvases exactly match one regional paint")를 유지해야 합니다.
  - 휴대폰 그리기 비용(청크 칠하기 시간)

1. **결정 필요 항목 D1~D8:** 특히 D3(세계관 표현)과 D4(작업 순서)는 G4·U1 착수 전에 필요합니다.
2. **G0(아트 디렉션 규격서) 작성 승인:** 문서 작업입니다. 승인되면 `docs/` 새 파일로 작성하며, 청사진·가이드는 고치지 않습니다.
3. **G1(캐릭터) 시안 제작 승인:** 16×22 유지안. 시안은 스프라이트 미리보기와 실제 게임 화면이며, 게임 기본 그림은 승인 전까지 바꾸지 않습니다.

이 계획서 작성 중 게임 코드·그래픽·청사진·저장은 바꾸지 않았고, PR도 만들지 않았습니다.
