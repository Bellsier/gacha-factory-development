# 건물 디자인 개선 (PR #12) — 수정 전후 비교

- **수정 전:** PR #12 커밋 `335d345`
- **수정 후:** 이 브랜치

모든 게임 화면은 Chromium(Playwright)에서 같은 조건으로 실행해 찍었습니다.
- 버리는 브라우저 컨텍스트를 썼습니다.
- `Math.random`을 고정해 수정 전후의 마을 배치가 같습니다.
- 저장 쓰기와 `saveGame`을 꺼서, 실제 저장 데이터는 읽지도 쓰지도 않습니다.

시작할 때 볼 수 없는 건물은 그 컨텍스트의 메모리에서만 만들었습니다.
- 제작소 Lv1·3·6: 게임 규칙 `workshopBuildSpot`이 고른 자리에 둡니다.
- 감정소·박물관: 복구 단계를 0·1·2로 바꿉니다.

같은 그림을 바로 보려면 개발 서버에서 `tools/building-gallery.html`을 엽니다.
- 주소 옵션: `?style=classic`, `?scale=2`, `?res=1.5`
- 게임은 실행하지 않고 그림 코드만 불러옵니다.

## 최종 수정 검증 (비교 화면 · 실제 키 입력)

| 파일 | 내용 |
| --- | --- |
| `07-gallery-v2.png`, `07-gallery-classic-res1_5.png` | 고친 비교 화면. 건물과 캐릭터를 게임 렌더러와 같은 함수(`tdBuildSpriteSheet`, `tdVillageImage`, `tdDrawSprite`)와 같은 기준점(공방 4, 제작소·시설·집 3, 캐릭터 1 px)으로 그립니다. classic에서는 게임처럼 `res`를 쓰지 않습니다. |
| `play/<pc-v2·pc-classic·mobile-v2>-walls.png` | 실제 W/A/S/D 키 입력으로 걸은 화면. 건물마다 두 장입니다. `front`는 정면 벽으로 W를 누른 결과이고, `behind`는 뒷벽으로 S를 누른 뒤 건물 뒤에 선 모습입니다. |
| `play/*-wide.png` | 점검을 마친 뒤 공방 앞에 선 화면 |
| `play/*-keys.json` | 키 입력 기록. `isTrusted` 키 이벤트 수, 키를 누른 총 시간, 건물마다 앞·옆·뒷벽에서 멈춘 좌표와 예상 벽 좌표, 옆벽 쪽 이동 중 벽 안에 들어간 횟수, 그리기 순서를 담았습니다. |

**키 입력 점검 방법**
- Playwright의 Chromium에서 진짜 키 이벤트를 보냈습니다. 게임에 들어간 W/A/S/D keydown은 모두 `isTrusted: true`입니다.
- 캐릭터는 처음 나타난 자리부터 키 입력으로만 움직였습니다.
- 길은 게임의 `playerCanStand`로 미리 계산했습니다. 이 함수는 읽기만 합니다.
- 버리는 브라우저 컨텍스트를 썼고, 저장 쓰기는 꺼 두었습니다.
- 제작소 3채(Lv1·3·6)와 시설의 복구 단계는 그 컨텍스트의 메모리에만 만들었습니다.

**결과**
- **앞벽·뒷벽:** 모든 건물에서 정확히 벽 앞(발 높이만큼 떨어진 곳)에서 멈춥니다.
- **옆벽:** 원래 있던 모서리 미끄러짐(`CORNER_SLIP` 0.18)으로 모서리를 돌아 지나가거나, 박물관처럼 벽 앞에서 멈춥니다. 어느 경우든 벽 안에 들어간 순간은 0번입니다.
- **그리기 순서:** 정면에서는 캐릭터가 건물 앞에, 뒤에서는 건물 뒤에 그려집니다.
- **PC v2, PC classic, 휴대폰 v2:** 모두 콘솔 오류가 없습니다.
